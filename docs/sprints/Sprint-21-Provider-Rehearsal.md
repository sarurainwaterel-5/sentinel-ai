# Sprint 21 selected-provider review rehearsal

This is a new review harness, separate from frozen scripted coordinators and from
the 108-call Astra Chat Completions benchmark. It is not a production answer route.
All production, empirical acceptance and inference-opening flags remain false.

The fixed plan is 13 reviewed control candidates assessed through the selected
Responses statement/relevance roles, then six positive cases generated by Sol
and assessed by Astra and Terra. The maximum is 44 transport attempts, 4,096 output
tokens per attempt, 30 seconds per attempt, a 1,500-second outer budget and zero
SDK retries. No legacy document contents are submitted: inputs are the existing
13 reviewed synthetic source cases, bound to their approved review by fixed hashes.
Gold labels and human rationales are excluded from provider requests.

A structural rejection withholds the candidate. Malformed, refused, incomplete,
timed-out, over-budget or inconsistent results stop dispatch and preserve partial
evidence; there is no repair or fallback. Relevance must echo the exact context
digest. Source coverage and directional relationship references must be complete.
An escaped HTML helper retains exact candidate text and complete supplied context
for review, including withheld results; it cannot authorize publication.

Configure all three explicit role credentials in the process environment using
the existing selected-model mapping. The harness does not read dotenv or fall
back to the general application key. Credentials are excluded from all reports.
Run from the repository with the configured process environment:

```sh
PYTHONPATH=backend python -m evaluation.governed_answers.live_provider_rehearsal \
  --execute --output /absolute/private-0700-directory/new-run.json
```

The output must be new and outside the repository; its parent must be owned and
mode 0700. The writer reserves it exclusively at mode 0600 before creating any
client. Every dispatch boundary checkpoints through file fsync, atomic replacement
and directory fsync. Interruption preserves the last complete checkpoint, possibly
with an uncertain attempted call. Do not blindly replay a run: a timed-out or
interrupted provider operation may have incurred usage. The trusted directory
owner remains part of the filesystem boundary; POSIX rename is not an atomic
compare-and-swap against a hostile same-UID owner.

A completed report is evidence awaiting review, not a passing release decision.
Failures and differences from reviewed controls must be retained. This protocol
does not establish source truth, general accuracy, model independence, real
retrieval correctness, full-context certification or production authorization.

Validation: 36 scripted tests passed before live execution, including durable
checkpoint failures/cancellation, unchanged frozen inputs, context mutation,
strict verdict/digest checks, budgets and escaped presentation.
