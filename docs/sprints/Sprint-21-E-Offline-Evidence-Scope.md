# Offline evidence-scope and catalog-race guard

The additive companion `backend/evaluation/governed_answers/evidence_scope_guard.py` composes scripted operator/catalog checks with the existing offline coordinator and separate relevance/presentation guard. No original packet, approved record, reviewed artifact, coordinator, renderer, route, document model or database is changed.

Call `evaluate_scoped_fixture` with an explicit question, AnswerScope, collection, complete synthetic sources/relationships, separately supplied authority/catalog readers, the injected offline coordinator, and a scripted relevance assessor. Readers must declare `execution_source=unit_test` and return typed fixture snapshots. These declarations and fixture objects are test contracts, not authenticated production authority.

The operator fixture identifies a scripted actor, organization, collection, permitted modules/topics and permission epoch. Requested scope must be explicit and permitted; wildcards and implicit all-domain requests do not broaden fixture permissions. Source metadata claiming authentication or another organization is never authority.

Catalog fixtures identify indexed documents by exact scope, file hash, per-document version epoch and exact per-chunk text hashes, with a global revision. Empty/missing, foreign, archived/pending/error, mismatched, duplicate, out-of-bounds or over-budget sources block the entire set before any candidate work. There is no silent filtering/truncation or partial-source fallback. Valid evidence is captured as an immutable snapshot and bound to the authority, request and catalog context.

Authority and catalog are read before candidate work, again before relevance assessment, and again before returning the guarded result. Changed permissions, actor/scope epochs, global revisions, lifecycle/version epochs, file hashes, status, document deletion or reader failures invalidate the snapshot and withhold the entire preview. Global revision changes detect scripted archive/restore and update/revert cycles even when final document values match. Complete snapshot comparison intentionally rejects unrelated catalog revision changes too; no automatic retries are implemented.

The guard retains the exact authorized evidence and scope in the coordinator result, then requires independently injected scripted question relevance. Evidence eligibility cannot replace relevance or statement admissibility. Failures expose bounded codes without foreign evidence or backend exception detail. Returned report JSON is immutable internally and copied on access. Public answer_text remains null and public claims remain empty; production authentication verification, enablement, release authorization, empirical acceptance and grounding stay false, with inference closed.

The current live document model has no monotonic catalog revision/lifecycle epoch. This companion does not add one, authenticate the proxy/operator, retrieve vectors/embeddings, access storage or implement a linearizable cross-store transaction. Revision counters are supplied by trusted scripted readers; unchanged or fabricated counters cannot prove absence of unseen live transitions. Future real adapters must derive permissions from server-authenticated context and provide genuine monotonic versioning plus suitable transactional/snapshot guarantees. A final fixture read cannot protect against real changes occurring after return.

Tests demonstrate permission/scope denial before generation, exact provenance checks, archive/update/delete/restore/revoke races, read failures, missing/malformed/non-scripted readers and relevance withholding, using only synthetic fixtures. These are enforcement tests, not empirical evidence for real authentication, retrieval authorization, relevance accuracy or production race safety. The production retrieval/catalog/race gate remains unimplemented in the frozen readiness checkpoint. No benchmarks, providers, credentials, production enablement, deployment, ADR-037 changes or PR #1 merge are authorized by this work.
