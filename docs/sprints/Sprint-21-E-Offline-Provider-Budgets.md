# Offline provider timeout/budget guard

`backend/evaluation/governed_answers/provider_budget_guard.py` adds request-local resource enforcement for separately supplied asynchronous scripted generation, statement-assessment and relevance-assessment callbacks. It constructs no real provider, client, credential configuration or runtime route, and changes no frozen code, records or reviewed artifacts.

Create one `OfflineProviderBudget` for a request, then await `execute(stage=..., request_json=..., provider=...)` for its stages. The three allowed stages share aggregate call, byte and overall deadline limits. Default caps are one call per stage, three total calls, one second per call, three seconds overall, 100,000 UTF-8 request bytes per call, 20,000 response bytes per call, 300,000 aggregate request bytes and 60,000 aggregate response bytes. These are offline test policy defaults, not approved production budgets or token/cost limits.

Only explicitly declared `execution_source=unit_test` asynchronous callbacks are accepted. Generation and assessment cannot reuse the same callback object across the session's history. This checks object separation for scripted fixtures, not authenticated model identity, hidden client sharing or independently configured production credentials. Incoming request JSON must be an object with unique keys and finite numeric values. It is canonicalized, size-checked and hashed before dispatch. Call/byte reservations occur before awaiting a callback; no concurrent calls, hidden retries or replacement providers are allowed. A failure permanently closes the request budget.

Responses are never truncated into partial success. They must fit per-call and aggregate UTF-8 limits and pass the existing strict candidate, statement-verdict or relevance-verdict schemas. Contradictory statement verdicts and relevance replies bound to a different request are rejected. Valid negative/uncertain semantic verdicts can complete transport validation without accepting a claim; the semantic/presentation guards still decide withholding. No generation metadata can confer budget or release authority. Callback receives a separate immutable request object; bypassing its immutability cannot alter the stored receipt.

Per-call deadlines use asyncio task supervision. On expiry or caller cancellation, the task receives cancellation and all results are withheld. A callback that suppresses cancellation may remain pending; it is quarantined, its late result discarded, and no later call can reopen the budget. The caller does not wait for that callback's cancellation cleanup. Callbacks must cooperate with the event loop: blocking Python/native code cannot be forcibly stopped here. Real production providers need separately reviewed SDK/transport/process isolation and resource controls. Response byte caps are checked after receipt and do not prevent a callback from allocating memory; these are not streaming, token, billing or process-memory budgets.

After separately validated fixture scope, admissibility and relevance, call `guard_presentation(presentation)`. It permits a preview only with successful, current receipts for all three stages bound to the exact preview: full generation premise/relationship inputs and candidate text/qualifications/lineage; the statement-assessment request and admissible verdict; and exact question/candidate/evidence/scope relevance context with a certain positive verdict. Missing, unbound, rejected, expired or failed receipts remove the entire preview. Partial earlier stage results are never a publication fallback. Successful finalization seals the session and preserves the exact prior fixture text/citations in an immutable display snapshot.

Generation receipts use `{premises, relationships}` matching the frozen fixture context. Statement receipts use the existing assessment-only request shape. Relevance receipts use the additive presentation guard's canonical context. This is a companion contract for cached scripted samples; it is not wired into the existing synchronous coordinator, actual providers or public answering routes. All callbacks in future integration must pass through the shared budget; this checkpoint does not claim that production provider composition or its budgets are implemented.

Every report remains unit_test with empirical_acceptance=false, production_enabled=false, release_authorized=false, semantic_grounding_verified=false and proposition-to-inference closed. No schema/transport completion is empirical or semantic acceptance. Tests cover stage/aggregate limits, UTF-8 caps, malformed/unavailable/refused responses, deadline expiry, caller/provider cancellation, late replies, concurrent calls, changed clocks, provider object reuse, altered request receipts, and final-preview binding/withholding. No live benchmark, credentials, embedding/vector/storage access, deployment, ADR-037 change or PR #1 merge is involved.
