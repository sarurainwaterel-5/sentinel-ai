# Sprint 21-G — Offline authority and catalog contracts

Baseline: `461df84c439c320eb83a7b4627f0db64eded4670`, branch `codex/sprint-21-b-contracts`.

`scope_catalog_contracts.py` adds strictly validated immutable explicit evidence scopes, scripted identities, authority snapshots, catalog/document versions and evidence chunks. `OfflineEligibilityGuard` captures a canonical request-bound context and rechecks its authority/catalog snapshots. Only exact organization/collection/module/topic grants can authorize fixture eligibility; grants are complete scope tuples rather than a cross-product of independent module/topic lists.

Capture validates the supplied principal against the reader's principal and grants before reading the catalog. Vector-like evidence candidates must match an indexed document's scope, file hash, lifecycle/content/index epochs, exact chunk locator and text SHA-256. Content and index epochs must agree. Empty manifests, missing or duplicate locators, stale versions, non-indexed states, oversized evidence sets, malformed snapshots and reader failures withhold eligibility. No credentials, HTTP headers or model metadata can substitute for a typed scripted identity or grant.

An issued immutable context includes question/request identity, authority, catalog, evidence and a canonical digest. The handle is bound to its issuing guard session. Cloned, cross-session or changed handles are denied. Repeated capture cannot replace the request. Each failure permanently closes the session; restoring a previous state after a denial cannot revive it. Permission epochs, catalog revisions and document lifecycle epochs detect observed archive/restore or delete/recreate changes even with identical bytes and final status.

Authority and catalog are read twice per checkpoint to reject observed torn snapshots. This is conservative optimistic validation, not distributed atomicity. Reader implementations must truthfully represent durable epochs; the guard cannot detect a store that conceals lifecycle changes or resets versions. A shared finite monotonic deadline covers capture and recheck, including reader/validation time as observed at the final check. Synchronous readers are not forcibly interrupted.

This is a separate offline contract checkpoint. It does not replace Sprint 21-F fixture readers or wire real stores into its coordinator. Every eligibility result has `authenticated_scope_verified=false`, `release_authorized=false`, `production_enabled=false`, and `proposition_to_inference=closed`. Fixture eligibility is neither semantic grounding nor permission to publish. There is no output publication API or final publish barrier.

Focused tests use in-memory readers only. They cover exact capture/recheck, foreign scope, spoofed/missing identity, revoked grants, unavailable readers, all non-indexed states, stale content/index/lifecycle versions, wrong hashes and locators, missing manifests, observed torn reads, archive/restore and delete/recreate epochs, terminal failures, forged contexts, request expiry, wildcard grants and metadata bypasses.

Next checkpoints: integrate these contracts with the offline async pipeline using scripted capabilities, then separately review real application identity and durable catalog/lifecycle/outbox migrations. Actual schema/backfill, vector synchronization, authenticated retrieval, publication consistency, provider integration, empirical acceptance and release authorization remain outstanding. No migration, database mutation, embedding, vector search, live provider, benchmark, deployment, production route change, frozen record/ADR-037 edit or PR #1 merge is part of this checkpoint.
