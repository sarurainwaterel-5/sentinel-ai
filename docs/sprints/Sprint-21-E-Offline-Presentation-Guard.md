# Sprint 21-E additive offline presentation guard

The guard in `backend/evaluation/governed_answers/presentation_guard.py` is a companion to the frozen offline coordinator. Call `guard_fixture(evaluation, assessor=scripted_assessor)` and render `result.to_component_report()` through the existing GovernedAnswerPanel. It does not modify the coordinator, renderer, approved review, frozen packet or production route, and no runtime route imports it.

Statement admissibility does not establish question relevance. The guard revalidates the original public response, evidence hashes and scope, claim text/qualifications, complete premise/evidence/relationship references, assessed inputs and exact fixture text. Only an admissible, complete original fixture reaches the separate relevance assessor.

The immutable relevance request contains canonical serialized question, candidate text/qualifications/lineage, exact evidence snapshot/provenance, scope, premises and relationships. It excludes generator metadata, validation claims, human labels and approval evidence. The separately injected assessor must be explicitly marked `execution_source=unit_test`; no real assessor implementation, provider factory, credentials or network capability is constructed here. This marker is a caller declaration, not authenticated proof of assessor behavior or organizational independence.

A relevance verdict requires the exact request SHA-256, strict `answers_question` and `uncertain` booleans, and a bounded nonblank display reason. Missing assessors; non-scripted declaration; unavailable, refused, timeout or failed assessment; malformed responses; mismatched hashes; uncertain or negative verdicts; and changes to the original fixture during assessment all withhold the entire preview. Existing rejected fixtures never call the relevance assessor. No admissibility fallback is allowed.

A denied admissible fixture retains a disabled public response with a bounded `blocked_validation` reason, but no fixture claim or text. Invalid snapshot input yields no public/claim snapshot and the existing panel's rejection alert. Allowed fixtures retain the exact original preview text and complete citations. Guard outputs store immutable JSON snapshots and return fresh dictionaries, so later caller mutations cannot change the stored display record. No caller-supplied release or empirical flags are accepted by the result constructor.

The guarded report remains `execution_source=unit_test`, `empirical_acceptance=false`, `release_authorized=false`, `production_enabled=false`, `semantic_grounding_verified=false` and `proposition_to_inference=closed`. A supported-but-irrelevant statement is withheld when the scripted relevance assessment is negative. Scripted assessments test enforcement and presentation only; they do not establish an actual provider's semantic or relevance accuracy, authenticated identity, real retrieval authorization or production race protection.

The new proposed presentation packet exercises the six accepted controls, six rejected cases and the irrelevant case with this companion guard. The prior raw packet remains historical evidence of the frozen coordinator's ungated behavior. Presentation review/approval remains pending. Production question relevance, complete-context assessment, rendered presentation acceptance and every other release gate remain separate.
