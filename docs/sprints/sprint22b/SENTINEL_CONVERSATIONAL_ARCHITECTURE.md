# Sentinel conversational architecture — Sprint 22B

Baseline: 3202bf7f2e02fe3b1e93f75ff5ec85873ab1219b. The inspected 22A registry, SQLite evidence store, health evaluator and issued authentication handles remain authoritative. Existing Recall and Reason are single-question interfaces; the legacy retrieval service initializes external embedding/vector dependencies. Neither is imported by the new layer.

The additive `app/services/companion` package separates conversation persistence, authority, repository retrieval, deterministic response rendering and an explicit local FastAPI factory. The factory is not mounted into `app/main.py`; deployment and installed services are unchanged. The React Companion page is opt-in through `VITE_COMPANION_API_URL`; without configuration it explains that the local service is unavailable.

A trusted composition supplies a new GovernedAuthenticationSession per request, exact evidence scope, fixed tenant/application, explicit CompanionGrants, private ConversationStore, RepositoryKnowledge and ConversationManager. Never accept these settings from request JSON. Authentication is HTTP Basic through existing authentication; use a trusted local same-origin transport. The UI stores neither passwords nor history in browser persistence. Cross-origin hosting and production installation are not delivered.

Observer reads an atomic SRE snapshot. Investigator generates bounded rule hypotheses. Verifier checks independent structural rules. Architect checks allowlisted repository sources. Conversation Agent renders checked records with citations. Supervisor checks issued handles, explicit grants, quotas, deadlines and cancellation. These logical roles do not create autonomous agents or grant tools.

Sprint 21-F OfflineAsyncAnswerCoordinator accepts only scripted unit-test providers and stage-specific proposition schemas. It remains unchanged. Its contracts cannot authorize free-form runtime conversation. The bounded compatibility layer publishes deterministic repository records and structurally checked investigation reports; it does not publish arbitrary model prose. ConversationProvider is a future provider-neutral seam; supplied providers are not invoked while the release gate remains closed. There are zero paid or live model calls in this sprint. No semantic accuracy or live fluency acceptance is claimed.

Requests support bounded question retrieval, simple references to the latest user topic, history and configurable direct/friendly/technical tone. This is a functional limited multi-turn record conversation, not general ChatGPT-equivalent inference. Unknown topics return explicit insufficient evidence. Existing infrastructure has no token stream; final responses only. Browser cancellation suppresses stale display but an already submitted server turn may complete. Direct manager cancellation/deadline checks withhold before persistence.

API: `/companion/v1/capabilities`, `/conversations` GET/POST, `/conversations/{id}` GET/DELETE, `/conversations/{id}/turns` POST and `/investigations` POST. Incident selection is explicit through the investigation API; a dedicated incident picker is deferred. No tool execution endpoints exist. ADR-037 remains Proposed and proposition-to-inference remains closed.
