# Sprint 22: offline paper oversight v0.1

Status: first bounded implementation, November 15, 2026. Human report review and
actual TradingView export mapping remain pending. This is not a connected trading
integration or production authorization.

## Delivered surface

`backend/evaluation/trading_oversight/` contains a closed snapshot schema, bounded
local artifact reader, pure deterministic consistency evaluator, private JSON/HTML
report bundle and an explicit human-review receipt command. `tradingview.py`
separately captures manually supplied CSV bytes and framing metadata; it does not
create a normalized snapshot or infer account state. See
[TradingView workflow](TRADINGVIEW_PAPER_WORKFLOW.md).

The generated [snapshot schema](snapshot-v0.1.schema.json) describes the closed
Pydantic envelope. Runtime parsing additionally checks depth, bytes, duplicate
keys, safe integers, exact booleans, credential-shaped fields, UTC chronology and
Unicode; JSON Schema alone does not implement all these constraints.

The implementation reuses Trading's integer ticks/cents and audit-event conventions.
Python canonical digests are checked against fixed golden vectors generated by
the actual read-only Trading audit module, including UTF-16 key ordering. Selected
source hashes and Trading commit are retained in
`backend/evaluation/trading_oversight/fixtures/source-baseline.json`. Existing dirty
Trading work is preserved; this is not an attestation of a clean deployed producer.
The fixture policy hashes are synthetic, not the real risk/strategy policy values.

## What the evaluator establishes

- Explicit separately supplied organization/account/environment and policy-hash
  agreement; payload and bounded audit-chain self-consistency.
- Sequence/checkpoint consistency, epoch/account claims, provenance/clock-domain
  agreement, chronology and snapshot/account/quote freshness limitations.
- Known versus unknown exposure; missing reconciliation/protection and platform
  lock observations; duplicate proposals and invalid tick geometry.
- Explicit blockers for unresolved IMAF definitions, unverified source, strategy
  and actual account-risk configuration. No order-authorizing risk receipt.

Candidate/context hashes remain opaque claims unless complete source input is
independently rederived. Audit self-consistency is not source authentication or a
trusted historical anchor. No full strategy reconstruction, tick-economics/cost
calibration or independent account authorization is claimed. The initial evaluator
always reports BLOCKED because IMAF operational definitions are unapproved; it
cannot produce APPROVED_TO_TRADE. TradingView paper settings are not inferred from
Sentinel Trading AI's MNQ research defaults.

## Security and operational behavior

- No database, broker, HTTP, model, shell or execution/control client imports.
- No environment credential discovery, deployment hooks or import-time execution.
- Local reads reject symlinks in every path component, nonregular files, changes
  during read and excessive bytes; FIFOs cannot hang the reader.
- Outputs use a new directory `0700`, exclusive files `0600`, fsync and cleanup on
  incomplete bundle creation. Prior output is never overwritten.
- HTML escapes imported text, permits no scripts/network and presents findings
  separately from collapsible full JSON details.
- Exact input/expectations/report hashes and checker-source hashes bind the report.
  A later user-requested accept/reject/defer receipt binds that exact artifact;
  it never changes policy, execution mode, financial state or the original report.
- CLI exit 0 means an offline artifact was created, not that evidence is safe or
  trading is approved. Invalid input/operation returns nonzero without printing
  source payloads or validation details that could contain private data.

## Verification

73 focused tests passed across contracts, reports, independent adversarial safety
checks and TradingView CSV framing/capture. Tests include malformed/duplicate/deep
JSON, numeric booleans, scope/policy tampering, unanchored/replayed audit, unknown
exposure, stale account state hidden behind a fresh export, invalid proposal bounds,
JS canonical digest vectors, escaped rendering, symlink ancestors/FIFOs, offline
socket-denied inspection, exclusive receipts, file permissions and output reuse.

A real CLI run produced a deterministic synthetic report with integrity
SELF_CONSISTENT_UNANCHORED, overall BLOCKED, source unauthenticated, strategy/risk
UNVERIFIED and all execution/live authority false. No human receipt was created
for that report by the implementation agent. A separately executed synthetic CSV
capture verifies command wiring only, not actual TradingView schema conformance.

No existing application route was changed. No full backend regression, actual
TradingView account test, authenticated provider input, source DB integration or
market performance test is claimed by this focused result.
